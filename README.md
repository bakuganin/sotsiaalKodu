# Sotsiaalsete Teenuste Kodu

Русская версия корпоративного сайта: React + TypeScript + Vite, SPA без админки. Главная — `/`, отдельные страницы услуг — `/services/` и команды — `/team/`. Мегаменю ведёт к нужному направлению на странице услуг, например `/services/#home-help`. Краткие карточки на главной по-прежнему открывают диалоги `/#/services/home-help`; кнопки «Назад» и «Вперёд» браузера работают.

## Посмотреть и запустить

Локальный адрес: **http://127.0.0.1:5173**.

```powershell
npm ci
npm run dev
```

Проверка и сборка:

```powershell
npm run build
npx playwright install chromium
npm test
```

Сборка появляется в `dist/`. Для отдельных страниц создаются `dist/services/index.html` и `dist/team/index.html` с собственными заголовками и описаниями: прямые ссылки и обновление страницы работают на статическом хостинге, который обслуживает `index.html` внутри каталогов. `npm run preview` запускает просмотр сборки. Исходные материалы проекта в `../sources/` не изменялись.

## Что реализовано

- Preloader отключён: страница открывается без загрузочного экрана и обязательной задержки. Сигнал `site:ready` отправляется при запуске приложения, не ожидая `window.load`. Материалы старого загрузчика сохранены; архивное описание — `design/PRELOADER.md`.
- При первом открытии вкладки остаётся предупреждение «Сайт ещё в разработке». Оно плавно появляется, закрывается кнопкой «Перейти на сайт», крестиком, Escape или нажатием на фон; подтверждение хранится в `sessionStorage` (`sotsiaal-development-notice-dismissed`).
- Главная, четыре направления услуг с подробностями, информация о компании, ценности, порядок обращения, команда, встречи и курсы, FAQ, контакты.
- Компактное мегаменю услуг на компьютере и полноэкранное мобильное меню с крупной типографикой, отдельной прокруткой и плавным открытием/закрытием. Клавиатура, Escape, возврат фокуса и настройка уменьшения движения поддерживаются.
- Отдельные страницы услуг и команды используют общий логотип, меню, подвал и форму записи. Переходы между страницами выполняются без перезагрузки; ссылки на разделы главной прокручиваются плавно.
- Кнопки «Написать нам» и «Связаться с нами» открывают общую форму; «Предложить тему» открывает её с выбранным направлением курсов. Форма плавно появляется и закрывается, сохраняет положение страницы и возвращает фокус на вызвавшую её кнопку. Настройки уменьшения движения отключают анимацию.
- Просторный монохромный дизайн по последнему концепту: две светло-серые плоскости в первом экране, крупный стеклянный дом с ростком, выразительные заголовки с серыми акцентами, чередование белых и чёрных секций, капсульные кнопки с контрастной стрелкой.
- Статичная ветка с листьями объединяет принципы помощи; полупрозрачные карточки оставляют фон видимым. Сценарий адаптирован под социальные услуги, без товарных карточек добавок и неподтверждённых показателей из референса.
- Основное содержимое ограничено контейнером до 1320 px. Внешняя ширина первого экрана увеличена на 15%, до 1518 px: на компьютере две равные квадратные панели со скруглением всех углов 44 px и отступом сверху 12 px. Контент и шапка выровнены по общему внутреннему контейнеру 1320 px; вокруг них оставлено дополнительное пространство. На узких экранах внешняя ширина уменьшается по доступному месту. На планшете высота адаптируется к содержимому, на телефоне используется вертикальная компоновка с внешним отступом 8 px. Фоны остальных секций занимают всю ширину экрана.
- В разделе команды размещены фотографии Натальи Умаровой и Эдуарда Иста, предоставленные заказчиком; оригиналы сохранены без редактирования.
- Команда оформлена раскрывающейся галереей по последнему референсу: крупный заголовок по центру, цветной активный портрет с тёмной панелью и узкие чёрно-белые неактивные портреты. Выбор по нажатию или клавиатурой, без автоматического перелистывания; на телефоне карточки раскрываются вертикально. Компонент `src/team/TeamSection.tsx` строится из массива команды и поддерживает добавление участников.
- Переключение команды занимает 650 мс: размеры карточек и фотографий изменяются согласованно, текст и подписи плавно появляются. Текст сохраняет ширину во время раскрытия; закрытые панели исключены из навигации и дерева доступности через `inert` и `aria-hidden`. При системном ограничении движения переключение мгновенное.
- Индивидуальные карточки команды описывают подтверждённый профессиональный опыт: Наталья Умарова — социальная педагогика, практика помощи семьям и обучение; Эдуард Ист — право и муниципальное управление. На странице `/team/` есть источники; сведения и редакционные решения зафиксированы в `design/TEAM-PROFILES.md`.
- На главной, странице услуг и странице команды добавлены однократные композиционные анимации: раскрытие hero как разворота, фигурные маски иллюстраций, сборка ветвей и линз, мягкая перспектива карточек. Исходный домик остаётся фотографией с лёгкой реакцией на мышь; WebGL и preloader отключены. Подробности — [design/MOTION.md](design/MOTION.md).
- Адаптивная версия для телефона и компьютера; увеличение текста, клавиатурная навигация, ограничение анимации при системной настройке reduced motion.
- Круглая кнопка доступности закреплена слева внизу вместо AA в шапке. Панель предлагает размер текста до 200%, светлый/тёмный контраст, четыре цветовых режима, простой шрифт, интервалы, подчёркивание ссылок, крупный курсор, отключение движения, скрытие декоративных изображений и линию чтения. Настройки сохраняются локально, валидируются и сбрасываются одной кнопкой. Панель доступна и поверх календаря; фокус остаётся внутри и возвращается при закрытии. Подробности проверок — `design/ACCESSIBILITY.md`.
- Интерактивная демонстрация записи: услуга → будущий будний день → пример времени → контакт → предпросмотр.
- Публичные телефон и email открывают соответствующие приложения. Отправку письма выполняет сам посетитель.
- Локальные шрифты и изображения. Нет аналитики, рекламных cookies и сетевой отправки формы.

## Граница текущей версии

**Календарь демонстрационный.** Он не читает расписание сотрудников, не отправляет заявки, не резервирует время. Примеры дат и времени помечены в самой форме. Контактные данные используются только в памяти открытого диалога, очищаются при закрытии и не записываются в браузерное хранилище. В localStorage сохраняются только настройки доступности (`kodu-accessibility-v1`).

Мероприятия не выдуманы: показано состояние «расписание готовится». Имена и роль членов правления подтверждены; в карточках размещены предоставленные заказчиком фотографии команды. `kodu` и графический знак — предложенное визуальное решение, которое нужно согласовать как бренд.

Для демонстрационной версии включён `noindex, nofollow`, чтобы сайт не индексировался до официального запуска.

## Контент и будущие пять языков

- `src/content/ru.ts` — тексты страниц, услуг, команды, FAQ, сообщений и метаданных.
- `src/content/index.ts` — реестр доступных переводов и отдельные факты организации.
- `src/booking/ru.ts` — тексты сценария записи.
- `src/accessibility/ru.ts` — тексты панели доступности.
- `src/booking/BookingDialog.tsx` — отдельный компонент записи.
- `src/content/ru.ts` → `calm` — тексты нового визуального концепта. Описание новых изображений и промпты — в `design/CALM-ASSETS.md`.

Сейчас доступен только русский. Состав остальных языков ещё не утверждён. Для локализации добавить согласованные словари, общий выбор языка для страницы и записи, адреса языковых версий, локализованные метаданные и `hreflang`. Уже сейчас интерфейс не содержит ложных переключателей на отсутствующие переводы. Даты календаря форматируются через Intl с явным часовым поясом `Europe/Tallinn`.

Будущая CMS может возвращать те же сущности: услуги, сотрудники, события, общие контакты и переводы. Тексты и сведения отделены от оформления, поэтому подключение управления не потребует полной пересборки дизайна. В текущий объём CMS и административные страницы не входят.

## Настоящая запись без собственной админки

Сначала согласовать, где сотрудники будут вести расписание. Возможны существующая система записи или управляемый календарь с серверной интеграцией. Сам SPA не должен хранить ключи календаря и решать, свободен ли слот.

Для рабочего сценария нужны:

1. Список услуг и исполнителей, длительность встреч, перерывы, рабочие часы и исключения.
2. Серверный источник свободных слотов и атомарное бронирование, предотвращающее двойную запись.
3. Подтверждение, отмена и перенос встречи; согласованный канал уведомлений.
4. Утверждённые условия обработки обращений, минимальный набор контактных данных, сроки хранения и защита формы от автоматических запросов.

Раздел мероприятий остаётся отдельным от календаря личных встреч. Для редких инфодней удобнее карточки ближайших мероприятий с датой, языком, местом и записью. Месячная сетка имеет смысл при плотном расписании.
