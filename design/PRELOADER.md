# Загрузочный экран Sotsiaal Kodu — архив

**Отключён по просьбе заказчика 16 сентября 2026 года.** Загрузчик больше не встраивается в HTML и не блокирует страницу. Параметры `?loader=1` и `?loader=0` больше ничего не переключают; маркер `sotsiaal-preloader-seen` не записывается. SVG, стили, скрипт и прежние тесты сохранены как архив; тесты загрузчика пропускаются.

Страница сразу получает `data-site-ready="true"`. При запуске приложения отправляется событие `site:ready`, без ожидания `window.load` и минимального времени показа. Предупреждение «Сайт ещё в разработке» остаётся отдельным действующим модальным окном, появляющимся один раз за вкладку до подтверждения пользователем.

## Архивное описание отключённой реализации

Описание ниже относится к прежней версии и не описывает текущую загрузку сайта.

Загрузчик работает на главной и прямых адресах `/services/`, `/team/`. SVG, стили и небольшой независимый скрипт встраиваются в HTML плагином `inline-site-preloader` из `vite.config.ts`. Отдельного запроса за иллюстрацией, шрифтом или библиотекой анимации нет. React для запуска или аварийного скрытия не нужен.

В собранном сайте основной CSS во время показа загрузчика загружается без блокировки первого кадра и применяется по завершении запроса; `window.load` по-прежнему ждёт его. При пропуске загрузчика CSS блокирует отображение как обычно, чтобы не показывать страницу без оформления. Для отключённого JavaScript сохранено обычное подключение через `noscript`.

## Просмотр

- `/?loader=1` — принудительный показ, включая повторное обновление.
- `/?loader=0` — отключение, без записи признака просмотра.
- Обычный адрес — один показ за вкладку; маркер `sotsiaal-preloader-seen=1` хранится в `sessionStorage`. Для нового первого показа можно открыть новую вкладку или удалить этот маркер.

## Оформление и слои

`src/preloader/illustration.svg` — самостоятельная многослойная векторная иллюстрация в финальном состоянии. Её можно заменить без изменения логики загрузки. Чтобы сохранить текущую последовательность, используйте классы `loader-hand-wipe`, `loader-soil-clump`, `loader-stem-draw`, `loader-leaf-left`, `loader-leaf-right`, `loader-leaf-top` и `loader-plant` либо адаптируйте только CSS под новые слои.

`src/preloader/preloader.css` — оформление и движение. Палитра задаётся в начале файла:

```css
--loader-background: #f7f5ec;
--loader-primary: #57791d;
--loader-secondary: #93b947;
--loader-shadow: #263711;
--loader-bark: #b6a38a;
```

Иллюстрация имеет размер 168 × 168 px на телефоне и 240 × 240 px начиная с 640 px. Ладонь раскрывается маской за 600 мс; земля появляется с 450 до 900 мс; маска стебля рисуется с 800 до 1350 мс; боковые листья раскрываются с 1150 до 1700 мс; верхний — с 1550 до 2100 мс. После паузы до 2400 мс покачивается только растение, ладонь и земля неподвижны.

## Завершение и доступность

`src/preloader/bootstrap.js` запускается в `<head>` до первого отображения приложения. Обычное скрытие начинается после обоих условий: прошло 2400 мс и сработал `window.load`. Исчезновение занимает 650 мс. Независимый предел в 8000 мс включает исчезновение: если загрузка зависла, переход начинается на 7350 мс, окончательное снятие экрана и блокировки происходит не позднее 8000 мс работы таймеров. После возвращения в долго неактивную вкладку просроченный экран снимается сразу.

При системном уменьшении движения или сохранённой настройке сайта показывается готовая статичная композиция; вместо обязательных 2400 мс используются 150 мс и короткое исчезновение. Событие загрузки или аварийный предел по-прежнему учитываются. Ошибки доступа к хранилищам не блокируют страницу. Без JavaScript экран не показывается.

Контейнер имеет `role="status"` и понятное имя, SVG скрыт от вспомогательных технологий. Во время загрузки приложение невидимо и недоступно для фокуса; при исчезновении видно под экраном, но остаётся `inert` до завершения.

Кнопка доступности, вынесенная за корень приложения, также скрыта до готовности. Модальное окно услуги при прямом переходе по её адресу открывается только после загрузчика.

После скрытия (включая пропуск) один раз отправляется `window`-событие `site:ready`. На `<html>` устанавливается `data-site-ready="true"`. Поздно подключившиеся компоненты сначала проверяют этот атрибут, чтобы не пропустить готовность:

```js
if (document.documentElement.dataset.siteReady !== "false") startAnimation();
else window.addEventListener("site:ready", startAnimation, { once: true });
```

Композиция с портретами и круги на ветке уже используют этот механизм. При последующих переходах по сайту загрузчик повторно не появляется и анимации работают обычным образом.
